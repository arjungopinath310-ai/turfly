2 · Before you type any command

Open PowerShell in the project folder

  1. Press the Windows key, type PowerShell, press Enter. (For the database commands marked "as Administrator", right-click Windows PowerShell → Run as administrator.)
  2. Go to the project folder (copy exactly, including the quotes): 
    cd "C:\Users\arjun\OneDrive\Documents\Arjun Claude\turfly"
  3. The prompt now ends with …\turfly>. Every command in this guide is typed here.

Reading the output

  • Green [ OK ] lines are good. Red [FAIL] lines always print a Fix: line with the next step.
  • To stop a program running in a window, click the window and press Ctrl + C (answer Y if asked "Terminate batch job?").
  • Copy text from PowerShell by selecting it with the mouse and pressing Enter; paste with a right-click.

3 · What runs on the PC

Turfly is four parts. start-all opens three windows; the database runs in the background.

Turfly public tunnelcloudflared. Connects the PC to Cloudflare and prints the public https://….trycloudflare.com address.
Turfly serverThe website and app back end on http://localhost:3000. Shows sign-in codes and messages.
Turfly remindersEvery minute: frees unpaid slot holds after 5 minutes, completes past matches, sends reminders.
PostgreSQLAll data. A Windows service that starts by itself; no window.
If this stops……this is what people notice
Public tunnelNobody outside your Wi-Fi can open the site ("site can't be reached" or Cloudflare error). On the PC, http://localhost:3000 still works.
ServerCloudflare shows "Bad gateway" / error 1033 / 502. Nothing works.
RemindersThe site works, but unpaid holds block slots longer, finished matches don't become "completed" (no reviews), reminders aren't sent.
DatabasePages show an error; status.ps1 reports "Database is not running".
The PC sleeps, restarts or loses internetEverything stops. After a restart run start-all again (it gives a new public address).
Keep the PC awake while it hosts Turfly. Settings → System → Power → "When plugged in, put my device to sleep after": Never. Closing the laptop lid may also sleep it: Control Panel → Power Options → "Choose what closing the lid does" → Do nothing (when plugged in).

4 · Starting and stopping

Start (after turning the PC on, or after stop-all)

cd "C:\Users\arjun\OneDrive\Documents\Arjun Claude\turfly"
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1

It checks the database, starts the tunnel and waits for the public address, saves it in .env, opens the Turfly server and Turfly reminders windows and waits until the site answers. It ends with:

Turfly is running.
Public address: https://some-random-words.trycloudflare.com

Share that address. It can take up to a minute to work on other devices. Leave the three windows open (you can minimise them).

Stop

powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1

Stops the server, reminders and tunnel; the windows stay open showing their last lines, close them. The database keeps running (that's fine).

Check

powershell -ExecutionPolicy Bypass -File scripts\status.ps1

Checks the database, the server, the reminders loop, the public address and free disk space, and prints a fix for anything that fails.

Doing it by hand (if a script fails)

Open three PowerShell windows, cd to the turfly folder in each, then:

WindowCommand
1 · tunnel (start first)& 'C:\Program Files (x86)\cloudflared\cloudflared.exe' tunnel --url http://localhost:3000 --no-autoupdate
Copy the https://….trycloudflare.com address it prints, then in another window:
powershell -ExecutionPolicy Bypass -File scripts\set-public-url.ps1 https://THE-ADDRESS.trycloudflare.com
2 · servernpm.cmd start (if there is no build yet or the code changed: npm.cmd run build first)
3 · remindersnpm.cmd run cron:local

5 · When the public address changes

The free Cloudflare "quick tunnel" gets a new random address every time it starts, and Cloudflare can delete one at any time (the tunnel window then repeats ERR … Tunnel not found). start-all handles the website side automatically. After a change:

  1. Tell people the new address (players, turf owners, testers). Old links stop working.
  2. Android app: the address is built into the APK. Rebuild and reinstall: 
    cd mobile
npm.cmd run build:debug
    The new APK is mobile\dist\turfly-1.0.0-debug.apk; send it to the phones and install over the old one.
  3. Real Razorpay keys only: Razorpay Dashboard → Settings → Webhooks → edit the webhook URL to https://NEW-ADDRESS/api/payments/webhook. Without this, payments are not confirmed. Razorpay retries failed webhooks for a while; once the URL is fixed, late payments are confirmed or refunded automatically.
  4. Google sign-in only (if configured): Google Cloud Console → Credentials → OAuth client → add https://NEW-ADDRESS/api/auth/callback/google.
Permanent fix: buy a domain (e.g. turfly.in, about ₹800/year), add it to a free Cloudflare account and create a named tunnel. The address then never changes, and steps 1–4 are never needed again. Details: docs\PRODUCTION.md.

6 · Updating Turfly to a new version

When new code has been pushed to GitHub (by you, a developer or an assistant), one command does it all and keeps the public address:

cd "C:\Users\arjun\OneDrive\Documents\Arjun Claude\turfly"
powershell -ExecutionPolicy Bypass -File scripts\restart-server.ps1 -Update

It backs up the database, gets the new code (git pull), stops the website, installs packages (npm.cmd ci), applies database changes (npm.cmd run db:migrate), builds and starts the website again. The site is offline for about 2 minutes. If a step fails it stops and says so. The same steps by hand, if you ever need them:

powershell -ExecutionPolicy Bypass -File scripts\backup-db.ps1   # 1. safety copy of the data
git pull                                                         # 2. get the new code
powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1    # 3. stop (the build replaces files in use)
npm.cmd ci                                                       # 4. install exactly the listed packages
npm.cmd run db:migrate                                           # 5. apply database changes, if any
npm.cmd test                                                     # 6. optional: quick self-check
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1 -Rebuild   # 7. build and start (new address)
  • Step 2 says "Your local changes would be overwritten"? Someone edited files on this PC. Run git status to see which; keep a copy, then git stash and pull again.
  • Step 4 fails with EPERM … query_engine? Turfly is still running; run stop-all again and repeat step 4.
  • If the new version misbehaves, go back to the previous one: git log --oneline -5, pick the previous commit id, git checkout THAT-ID, then steps 4 and 7. (Database changes are not undone; restore a backup only if really needed, section 8.)

Android app updates

Website changes appear in the app automatically (it shows the live site). Only changes inside mobile\ or a changed address need a new APK (cd mobile, npm.cmd run build:debug). For Google Play builds see docs\ANDROID.md.

7 · Admin work inside the app

Everyone must sign in

Opening Turfly, on the website or in the app, shows the sign-in page first. Visitors must sign in (mobile number + code, or Google once it is set up) before they can see turfs, book or use anything else. Afterwards they return to the page they asked for, so shared links (split payments, team invites, turf claims) still work. These pages stay open without signing in, because Razorpay, Google and the Play Store check them, and none of them shows turfs: /login, /about (what Turfly is, with a sign-in button), /legal/…, /contact and /account/delete. When Razorpay or Google asks for your website or home page, give the /about address. The rule lives in src\lib\access.ts.

Players and turf owners see different apps

The sign-in page asks "I want to play" or "I own or run a turf". The choice is remembered on that phone or computer and decides what the person sees; it never gives extra permissions.

  • Players land on a search page and see Find turfs, My bookings, Teams and Find players. They never see owner options.
  • Turf owners land on their dashboard and see Dashboard, Calendar, Bookings, My turfs and Analytics. An owner with no turf yet gets two buttons: Find my turf (ask to manage a turf that is already listed) and Add my turf.
  • On phones both get a tab bar at the bottom of the screen. Owners and admins can change side from the account menu ("Switch to player" / "Switch to turf owner"). The footer link For turf owners opens sign-in with the owner choice ticked.

Signing in as admin

  • Phone numbers listed in ADMIN_PHONES in .env become admin when they sign in.
  • In demo mode the sign-in code is not shown on screen for admins and real turf owners (for safety). Look in the Turfly server window for a line like [otp] +91XXXXXXXXXX → 123456. With real SMS (MSG91 keys set) the code arrives by SMS.

Real turfs added from public information

Real turfs within about 20 km of Manjeri and Malappuram are listed as unclaimed: players see the name, address, phone, opening hours, facilities and a Directions button, but cannot book. Each listing names its sources (TapTurf, OpenStreetMap). When an owner gets in touch, send them the turf's claim link from /admin/turfs; after you approve the claim they manage it and can turn on bookings.

  • Reported price: on /admin/turfs, fill "Reported price" (lowest ₹ per hour, plus a note such as "₹1,200 after 6 PM") for turfs that don't manage bookings here, for example after calling the turf or reading recent reviews. It shows as "~₹… reported / hour" with the date, never as a confirmed price, and is ignored once the owner sets real prices. Leave it empty and press Save to remove it.
  • Closed or wrong listing: type a reason and press Hide; it disappears from search. "Show again" brings it back.
  • An owner asks to manage a listed turf (Find my turf): the request appears under Listing claims on /admin/turfs with what they wrote. Call the turf's public number to confirm, then press Approve & transfer. The turf moves to their dashboard and they can turn on bookings.

To add or correct many at once, edit prisma\data\turfs-manjeri-malappuram.json (exact map position needed) and run:

npx.cmd tsx scripts/import-turfs.ts prisma/data/turfs-manjeri-malappuram.json --dry-run   # shows what would change
npx.cmd tsx scripts/import-turfs.ts prisma/data/turfs-manjeri-malappuram.json             # writes it

It is safe to run again: it never touches turfs that have been claimed, matches a turf already listed at the same spot instead of adding it twice, and keeps phone numbers and reported prices entered in the admin pages. Make a backup first (section 8). To add a single turf, use "Add unclaimed listing" on /admin/turfs instead.

Turf locations use DIGIPIN

Turfly uses India Post's DIGIPIN instead of a street address or latitude/longitude: a 10-character code (for example MC9 4P82 MJK) for a spot of about 4 m × 4 m. Owners and admins type it, or stand on the pitch and tap Use my location; "Check it on the map" confirms the spot. A turf's DIGIPIN can be found at app.indiapost.gov.in/digipin. Turf, booking and checkout pages show the area, town and DIGIPIN (tap to copy), Directions still open the exact spot.

Sample turf for sales demos

Turfly Showcase Arena (Sample) shows what a turf looks like when it runs fully on Turfly: online booking with live slots, a 7-a-side pitch that splits into two 5-a-side pitches, peak / early-bird / weekend prices, floodlights till 1 AM, photos, about two months of bookings (online, phone and walk-in, including cancellations with refunds and a few no-shows), verified reviews and a planned maintenance block. It carries the "Demo listing" badge.

  • To show a turf owner the owner side: sign in with 9000000001 and choose "I own or run a turf" (the demo code works while DEMO_OTP is on). Show Dashboard, Calendar, Bookings and Analytics.
  • To refresh it so the history ends today (do this before an important demo): 
    npx.cmd tsx scripts/seed-showcase.ts
    It replaces only the sample turf and its own sample players (numbers +91 90000001xx); nothing else is touched. Make a backup first (section 8).
  • To remove it: Admin → Turfs → type a reason and press Hide on the sample turf.

Turf photos

The first photo of a turf is its thumbnail in search; turfs without photos show a drawn pitch. Owners add photos under My turfs → (turf) → Photos ("Add photos" picks them from the phone; they are shrunk before upload). Admins can do the same for any listing: on /admin/turfs click add photos under the turf's name. Only use photos you took or have permission to use (photos on Google Maps or other sites belong to whoever took them). Photos are stored in the uploads folder of the project; backup-db.ps1 zips them next to each database backup.

The search box matches turf names only; towns, PIN codes and facilities are separate filters.

8 · Backups and restore

Make a backup

powershell -ExecutionPolicy Bypass -File scripts\backup-db.ps1

Saves backups\turfly-YYYYMMDD-HHMM.dump and keeps the newest 14. The turfly folder is inside OneDrive, so backups are also copied to your OneDrive cloud storage. They contain personal data (phone numbers, bookings): keep your Microsoft account secure and don't share the files.

When: before every update (section 6), and at least weekly while real people use the site.

Restore a backup (replaces ALL current data)

Restoring wipes everything that happened after the backup (bookings, payments, sign-ups). Make a fresh backup first in case you need to undo.
powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1
powershell -ExecutionPolicy Bypass -File scripts\backup-db.ps1
& "C:\Program Files\PostgreSQL\16\bin\pg_restore.exe" --clean --if-exists --no-owner -d "postgresql://turfly@localhost:5432/turfly" backups\turfly-YYYYMMDD-HHMM.dump
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1

It asks for the database password: it is in .env, in DATABASE_URL between turfly: and @localhost.

Moving to another PC

  1. Install the tools from section 2, then git clone https://github.com/arjungopinath310-ai/turfly.
  2. Copy .env from the old PC (it is not on GitHub; keep it private). Create the database user with scripts\setup-local-db.ps1.
  3. npm.cmd ci, npm.cmd run db:migrate, restore the latest backup (above), then start-all -Rebuild.

9 · Troubleshooting

First run status.ps1; it names the broken part. Then find the symptom below.

SymptomLikely causeFix
Public address: "This site can't be reached" / DNS errorQuick tunnel expired, or the PC is asleep or offlineWake the PC, check internet, then stop-all → start-all. Share the new address (section 5).
Tunnel window repeats ERR … Tunnel not foundCloudflare deleted the quick tunnelstop-all → start-all.
Cloudflare page "Bad gateway", error 502 or 1033Tunnel is up but the server is notstop-all → start-all. If it repeats, read the Turfly server window (section 10).
start-all: "Port 3000 is already in use"An old server is still runningstop-all, then start-all. Still blocked: Get-NetTCPConnection -LocalPort 3000 -State Listen, then Stop-Process -Id OwningProcess-number.
status: "Database is not running"; pages show errorsPostgreSQL service stoppedPowerShell as Administrator: Start-Service postgresql-x64-16. If it won't start: check free disk space and the logs in C:\Program Files\PostgreSQL\16\data\log.

Sign-in returns to the login page, or a "callback" errorNEXTAUTH_URL in .env differs from the address in the browserset-public-url.ps1 with the address in the browser bar, then restart-server.ps1.
No sign-in codeDemo mode: admins/owners get it in the server window. Real mode: SMS not configuredRead [otp] lines in the Turfly server window. For real SMS set the MSG91 keys (section 11).
"Too many requests" when asking for a codeAnti-abuse limits: 5 codes/hour per phone, 30 s between codes, 10/hour per networkWait up to an hour, or clear that phone's codes (section 12).
Pages have no colours/layout, or errors mentioning .next, EINVAL, readlinkOneDrive turned build files into online-only placeholdersstop-all, then Remove-Item -Recurse -Force .next, New-Item -ItemType Directory .next, attrib +P -U .next, then start-all -Rebuild.
"npm.ps1 cannot be loaded… running scripts is disabled"Windows script policyUse npm.cmd; start scripts with powershell -ExecutionPolicy Bypass -File ….
EPERM: operation not permitted … query_engineThe running server locks a file that install/update wants to replacestop-all, then repeat the command.

Server window shows [env] WARNING linesInformation, not errors: demo mode on, business details missingFill those values in .env before real launch (section 11).

status: low disk spaceOld builds/backupsDelete .next-preview / .next-verify folders and old files in backups\; empty the Recycle Bin.

11 · The settings file (.env)

turfly\.env holds addresses, passwords and keys. It is never uploaded to GitHub. Open it with Notepad: notepad .env. After changing it, restart the website: powershell -ExecutionPolicy Bypass -File scripts\restart-server.ps1 (the address stays the same).

SettingMeaning
DATABASE_URLHow to reach the database (contains its password).
TEST_DATABASE_URLSame database with ?schema=test: where the automated tests write, so they never touch live data.
APP_URL, NEXTAUTH_URLThe public address. Set automatically by start-all / set-public-url.
NEXTAUTH_SECRET, CRON_SECRETRandom secrets. Changing NEXTAUTH_SECRET signs everyone out.
ADMIN_PHONESComma-separated +91… numbers that become admin when they sign in.
DEMO_MODEtrue: codes shown on screen, simulated payments. Set false only with real SMS and Razorpay keys.
DEMO_OTPFixed demo sign-in code, now 12345678, for players and turf owners on the website and in the app. Anyone who knows a number can sign in with it, so it never works for admin numbers (unless DEMO_OTP_ADMINS="true") and it stops by itself once real OTP SMS is set up or DEMO_MODE is off. Delete the line before launch.
MSG91_AUTH_KEY, MSG91_OTP_TEMPLATE_ID, MSG91_TPL_*Real SMS for sign-in codes and booking messages. Each message needs its own DLT-registered template: texts and steps in docs\Turfly-SMS-Templates.pdf (copy-paste version: docs\sms-templates.txt).
RAZORPAY_KEY_ID, _KEY_SECRET, _WEBHOOK_SECRETReal online payments. Leave empty in demo.
ALLOW_MOCK_PAYMENTSAllows the "simulate payment" buttons. Must be off for real money.
GOOGLE_CLIENT_*, WHATSAPP_*, RESEND_API_KEY, EMAIL_FROMOptional: Google sign-in, WhatsApp messages, email.
FCM_SERVICE_ACCOUNT_JSONOptional: push notifications to the Android app (see docs\ANDROID.md).
BUSINESS_NAME, SUPPORT_EMAIL, BUSINESS_ADDRESSShown on the legal pages. Required before real launch.
set-public-url.ps1 keeps the previous version as .env.bak. If an edit goes wrong: Copy-Item .env.bak .env -Force.

12 · Extra commands for emergencies

Open the database console

& "C:\Program Files\PostgreSQL\16\bin\psql.exe" "postgresql://turfly@localhost:5432/turfly"

Password: see section 8. Type \q to leave. Commands end with a semicolon. Read-only examples:

SELECT count(*) FROM "Booking" WHERE status = 'CONFIRMED' AND "startAt" > now();   -- upcoming bookings
SELECT code, status, "startAt" FROM "Booking" ORDER BY "createdAt" DESC LIMIT 10;   -- latest bookings
SELECT phone, name, role FROM "User" WHERE role = 'ADMIN';                          -- admins

Clear the sign-in code limit for one phone

DELETE FROM "OtpCode" WHERE phone = '+91XXXXXXXXXX';

Make someone admin (they must have signed in once)

UPDATE "User" SET role = 'ADMIN' WHERE phone = '+91XXXXXXXXXX';
Change data in the console only when this guide says so. Never edit bookings or payments by hand: money records must stay consistent. Use the admin pages for cancellations and refunds.
